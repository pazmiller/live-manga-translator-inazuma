# 2026-09-22 第二轮功能与玻璃界面验证

本轮落实单条校正、失败恢复、独立选区和可选翻页检测，并统一工具栏、旁注控件、编辑面板的 Liquid Glass 风格。

## 已验证的流程

| 范围 | 检查与结果 |

| 后端离线 | 32 项 unittest 通过。包含无 key 重 OCR、放大尺寸上限、修正文本对所有引擎生效、响应校验、共享并发上限、错误脱敏、缺失 ID 补译、OCR 缓存过期及未知编号拒绝 |

| 视觉检查 | 通透/柔和工具栏、编辑面板、失败恢复界面、短长译文、深色和彩色气泡、纹理旁注。错误区域改到恢复按钮下方，不再遮挡操作。工具栏正常 680×192，恢复行出现时 680×228，示例错误状态 680×306 |

真实单条校正示例：保存的 OCR 原文为「明日はきっといい日になる」，改为「今日は必ずいい日になる。」后，接口返回修正后的原文，译文为「今天一定会是个好日子。」。另外五条保持存在，没有再截取桌面。

断流测试在收到第一条真实译文后切断响应，随后请求 `only_ids: [1,2,3,4,5]`，第一条没有再次发送给补译接口。翻页检测在用户确认前不调用翻译服务。最终追加验证也通过：查看原图后恢复上一版，会同步恢复工具栏状态和气泡交互；新页 B 翻译失败后恢复旧页 A 的结果，会保持隐藏，直到真正回到 A 的画面。

本轮真实六条首次翻译状态栏观测约 5.2–5.5 秒，包含当次 OCR 和服务响应波动。此前 2.9 秒的记录不作为本轮保证；本轮提速收益主要来自单条处理、只补缺失内容和已有缓存，未进行同条件统计基准。

## 测试边界

完整应用测试只注入自制漫画测试图，保留真正的裁剪、IPC、HTTP、OCR 和 DeepSeek 调用。网络失败测试只截断真实响应，不替换识别或翻译结果。模拟翻页通过改变受控图像亮度实现，并断言截图像素确实改变，避免隐藏窗口尚未重绘导致误判。

测试初期的可见编辑面板接收了桌面真实点击，误触关闭。追踪记录证明关闭来自 `isTrusted: true` 的背景点击，而不是保存逻辑。因此完整测试现在让原生窗口始终点击穿透，并关闭测试窗口的原生抢焦点；同时记录应用请求的鼠标命中决策。交互通过各窗口内部 DOM/Chromium 完成，不发送系统级合成鼠标。不能将这些决策断言描述为真实桌面的鼠标穿透手感验证。

尚未确认：实体桌面截图排除、Windows Acrylic 实际桌面合成效果、混合 DPI 多屏、原生滚轮阅读手感。Claude 和 Google 路径有模拟接口测试，本轮未做真实服务验证。翻页检测是缩略像素启发式，细小改动可能漏检，动画也可能触发；固定模式和手动翻译始终可用。

## 设计依据与实现边界

Apple 的 [Materials 指南](https://developer.apple.com/design/human-interface-guidelines/materials) 将 Liquid Glass 用于悬浮控制和导航层。本应用据此让工具栏、编辑面板与操作控件使用玻璃视觉，正文仍匹配漫画背景。Windows 11 22H2 起可为工具栏调用系统 Acrylic；CSS 提供高光边缘、渐变、分层透明度及减少动态/透明度的回退。这是 Windows 上的风格实现，不是 Apple 的原生折射引擎。
