# 2026-09-23 动态玻璃修正与验证

用户反馈上轮窗口和边框缺少流动与透明效果。检查确认旧材质主要依赖 79%–95% 不透明底色和静态圆角，不能满足这个要求。本轮重做背景来源、折射与交互光效。

## 实现

- 本地桌面缩略图经过按玻璃区域裁剪，传给自己的 renderer；背景不落盘、不走 OCR、不发给翻译服务。
- 圆角矩形位移场通过 SVG `feDisplacementMap` 弯折背景，中心保持清晰，弧形边缘产生透镜效果。它是光学近似，未声称物理精确或使用 Apple 原生渲染器。
- 指针与窗口移动驱动阻尼动画，改变高光位置和折射强度；按压、释放也有反馈。选区 6px 边框有移动亮光，中央始终透明。
- 通透底色降至 12%–18%，柔和档 34%–42%；文字输入区和旁注保留局部衬底。暗背景切换文字/控件颜色。
- 采用单项采样、窗口共用截图、每窗口最多 8 层和 120 万输出像素。交互附近约 150ms，空闲约 750ms；全屏 overlay 空白处和选区中央不误触高频采样。翻译期间暂停采样、撤掉旧纹理；静止后停止光学动画。
- 异步解码带版本号，失败/隐藏/清除后旧背景不能重新出现。跨屏和部分越屏区域退回透明高光，不拉伸错位图像。系统减少动态/透明度偏好生效。

主进程集成使用生成图片和模拟 HTTP，不启动 Python，也没有付费翻译调用。本轮没有修改翻译算法，不重复上一轮的 DeepSeek 实网测试。旧实网脚本的截图计数已区分外观采样与翻译截图，语法检查通过。

隐藏 Electron 通过 CDP 切换减少动态效果偏好时，观察到约 4 秒的样式同步延迟；测试等待文字主题稳定后才比较，避免把文字颜色切换当成折射效果。初版正交格线在左边框横向折射方向上没有纹理变化，后来增加斜线来验证该方向，保留严格像素断言。

## Windows 原生验证

短暂显示两个受控测试窗口，均设置鼠标透传且不抢焦点。先确认真实桌面截图中 20 个边缘标记全部属于测试图，再保存限定区域；没有保存完整桌面图或其他应用内容。

未排除测试窗口时，与背景图平均 RGB 差异为 32.339 / 255；启用截图排除后，差异降到 0.271 / 255，背景正确恢复。证明本机的窗口排除能防止采入自身形成递归画面。

此验证使用软件合成模式。首次硬件合成测试遇到 Electron `UnknownVizError`，因此不能将结果扩大为普通 GPU 路径、所有显卡或混合 DPI 多屏均通过。真实鼠标手感仍未通过系统级自动输入验证；集成测试只记录应用请求的命中决策，窗口实际保持穿透，以免干扰用户。

截图排除会使本应用在一些外部截图/录屏里不可见，这是当前桌面折射方案的副作用。旧 Windows、截图失败、跨屏区域仍可使用透明高光回退。

## 实现参考

[Electron 的透明窗口说明](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles) 明确说明 CSS 模糊不能处理其他应用。因此本轮给光学层提供实际背景纹理。

[Kube 的折射实现说明](https://kube.io/blog/liquid-glass-css-svg/) 提供曲面位移和边缘高光思路；也检查了当前 [liquidGL 作者仓库](https://github.com/naughtyduk/liquidGL)。没有引入 DOM 截图依赖或复制第三方图片，本项目使用自己的简化圆角位移场。
