# 2026-09-22 改进与验证

## 已复现与修复

| 场景 | 初版表现 | 现在的行为 |
|---|---|---|
| 短原文对应长译文 | 缩至 9px 后仍裁掉内容 | 默认 14px 最小可读字号，放不下转成可滚动旁注 |
| 黄色/深色气泡 | 统一白底矩形盖住原画风 | 校验背景后使用采样颜色，保留轮廓；复杂背景不覆盖 |
| 网点/条纹背景 | 2px 取样偶然落在条纹间，被误判纯色 | 扩大取样环；纹理回退到旁注 |
| 同组长短行 | 漏识别的单笔画残留在逐行遮罩外 | 同时验证整组背景，使用保守的整组文本遮罩 |
| 竖排列内碎片 | 按 x 排序导致同列片段上下颠倒 | 列优先、列内从上到下 |
| 小号注音 | 误识别数字混进正文 | 强尺寸/位置约束关联注音，仅保留其遮罩位置 |
| 等待进度 | 固定计时器声称 OCR 已完成 | 由后端真实事件更新，完整译文字符串到达即显示 |
| 取消、清除、重复 | 可能晚到追加旧结果或堆叠 | 请求中止、job 校验、相交选区替换 |
| Windows 鼠标穿透 | 依赖穿透窗口自己的 mousemove 唤醒 | 主进程轮询光标与命中区域，拖动期间锁定接收 |
| 四角缩放到最小尺寸 | 非左/上锚点也可能移动窗口 | 根据真实拖动角保持相对角固定 |

## 本机实测

Windows，Python 3.13.14，Electron；完整应用测试显示器坐标 2560×1440、缩放 100%。六气泡图片为脚本绘制的 1000×740 日文布局，含横排、竖排、长翻译、深色、彩色、纹理和边缘位置。

| 测量 | 结果 |
|---|---:|
| 改动前首次 OCR（包括模型加载） | 4.689 秒 |
| 改动前热 OCR | 1.455 秒 |
| 最后一轮预热后 OCR | 0.960 秒 |
| NDJSON 识别区域到达 | 0.982 秒 |
| 第一条 DeepSeek 译文到达 | 2.523 秒 |
| 六条全部返回 | 2.654 秒 |
| 相同图片/语言重复请求 | 18 毫秒，OCR 与翻译均命中缓存 |
| 完整应用 UI → 结果 | 状态栏约 2.9 秒，重复显示「已复用 · 6 处」 |

这是单机观察，未做统计负载基准；模型预热转移了首次加载成本，不能把差值全部解释为推理速度提升。接口计时不含真实屏幕截图和桌面绘制。缓存随进程结束清空，设置了容量上限，不将截图写入缓存。

两个真实竖排裁图来自 [manga-ocr 示例](https://github.com/kha-white/manga-ocr#examples)，下载自 assets/examples/01.jpg 与 02.jpg。最终耗时分别约 1.17s、1.43s。第一个样例的注音数字污染已消失，但 OCR 仍读出「穴.」，译文也因此有多余句点。第二个样例识别为「実戦剣術も一流です」。这两个样本不足以证明整页漫画准确率。

## 自动验证范围

- 16 项 Python unittest：纯色/深色/纹理、漏笔画遮罩、气泡边界、竖排/注音、分块 JSON、缺项拒绝、失败缓存隔离、目标语言缓存区分、取消、不合法请求、空 OCR、真实端点事件顺序、服务异常。
- 4 项 Node 测试：跨 UTF-8 字节 NDJSON、提前断流、负显示器原点及 150% DPI 转换、跨屏裁剪。
- Electron renderer：六类布局默认字体 17–24px，无裁字；长文字旁注、深色贴合、英文横排；拖动、原文对照、原图切换、字号 150%、关闭、迟到结果、重复选区、小窗口下长文滚动、380px 工具栏、取消和错误提示。
- 完整 main/preload/backend 测试：只替换屏幕图像输入，真实裁剪坐标、IPC、HTTP、OCR、DeepSeek、overlay；检查六个结果、重复复用、原图、清除取消、缩放到最小尺寸的锚点，以及主进程鼠标命中决策。

真实桌面截图测试未成功观察到测试页（捕获的是桌面其他内容），因此不计为原生截图通过。后续改用受控截图，避免再次识别用户桌面的无关内容。Windows 原生鼠标穿透手感、实体多显示器和混合 DPI 待人工验证。测试从未发出系统级合成鼠标事件。
